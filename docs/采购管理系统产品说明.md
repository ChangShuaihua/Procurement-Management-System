# 采购管理系统产品说明

| 项 | 内容 |
| --- | --- |
| 版本 | 0.2 草案 |
| 日期 | 2026-10-21 |
| 读者 | 产品、研发、测试 |
| 本期目标 | 采购员维护供应商、物料、协议价和合同，并按合同类型导出 PDF |

## 1. 背景与目标

企业生产计算机零部件，采购两类东西：进入生产的生产资料，以及公司运转所需的物品器材。两类东西共用一套供应商、品类、协议价和合同。

系统只给采购员使用。采购员登录后直接维护资料、登记已经谈妥的单价、起草合同并导出 PDF。

本期要完成四件事：

1. 记下供应商、物料和已经商定的单价。
2. 把单价写入合同，合同数据留在系统里。
3. 保密协议导出纯文本 PDF；多物品采购合同导出带明细的完整合同 PDF。
4. 合同主档保持稳定。以后增加合同类型时，只增加该类型自己的内容和版式。

## 2. 范围

本期模块：

| 模块 | 内容 |
| --- | --- |
| 组织与人员 | 组织树、签约主体、采购员账号 |
| 物料与品类 | 品类树、物料 |
| 供应商 | 供应商档案 |
| 定价 | 某供应商对某物料的一个当前协议单价 |
| 合同 | 保密协议、多物品采购合同、PDF 导出 |

不包含这些业务：

- 采购申请，以及申请审批
- 询价、报价和比价
- 邮件或其他消息通知
- 采购订单、收货、对账、付款、发票
- 折扣、阶梯价

采购员要买什么，直接做合同。价格在系统外谈定，再录入为协议价。系统不收集多家报价，也不排列、推荐供应商。

任何操作都不发邮件，包括开账号、改价、合同生效和导出 PDF。

## 3. 谁来用

只有一种使用者：采购员。

所有采购员看到同一套菜单，都可以维护组织、人员、品类、物料、供应商、协议价和合同。没有管理员、只读账号，也不按部门隔离数据。

登录使用账号和密码。系统初始化时提供一名采购员。之后由采购员自己新增同事账号。

停用某人后，该账号不能登录。系统不提供忘记密码的邮件。需要重置密码时，由另一名采购员在人员资料里设置新密码。

## 4. 使用流程

1. 建立组织，标明哪几个公司节点可以作为合同甲方。
2. 建立采购员账号。
3. 建立品类和物料。
4. 建立供应商。
5. 为“供应商 + 物料”录入当前协议单价。
6. 起草保密协议或采购合同。
7. 确认后生效，并导出 PDF。

## 5. 共同规则

1. 合同保存时，复制当时的甲方名称和地址、供应商名称和地址、联系人、物料名称、规格、单位、单价。之后修改资料或协议价，已保存合同不变。草稿里的某一行要改用新价格时，删掉该行，重新添加。
2. 一张采购合同只有一个供应商，明细是多行物品。
3. 采购明细的单价取该供应商对该物料的当前协议价。没有协议价的物料不能加入合同。单价不能在合同里手填。
4. 单价大于 0，最多 4 位小数。数量大于 0，最多 4 位小数。行金额 = 四舍五入(单价 × 数量, 2 位小数)。合同总价 = 各行金额之和，不能手改。币种为人民币。
5. 界面和 PDF 使用简体中文。

## 6. 组织与人员

### 6.1 组织

组织是一棵树，节点分为公司和部门。

| 字段 | 规则 |
| --- | --- |
| 编码 | 必填，全局唯一，创建后不可改 |
| 名称 | 必填 |
| 上级 | 根节点为空 |
| 类型 | 公司或部门 |
| 地址 | 公司选填。作为甲方时必填 |
| 可作为甲方 | 只有公司可以勾选 |
| 状态 | 启用 / 停用 |

不能把节点移到自己的下级。

停用的组织及其下级，不能作为甲方，也不能放入新人员。已有合同里的甲方名称保留。

### 6.2 人员

| 字段 | 规则 |
| --- | --- |
| 登录名 | 必填，全局唯一，创建后不可改 |
| 姓名 | 必填 |
| 密码 | 新建时必填 |
| 所属组织 | 必填，组织为启用 |
| 手机 | 选填 |
| 状态 | 启用 / 停用 |

人员不设角色。启用中的人员都是采购员。

一个人只属于一个组织。合同记录经办人姓名；人员改名后，已保存合同仍显示保存时的姓名。

## 7. 物料与品类

### 7.1 品类

品类是一棵树，用来给物料分类。编码全局唯一，创建后不可改。品类通过上级字段指向另一条品类，根节点的上级为空。

物料和品类是多对一。关联建在物料上：物料保存所属品类的编号，必填，一条物料只指向一个品类，一个品类下可以有多条物料。物料不单独复制一份品类树。

停用品类前，其下级品类和挂在上面的物料都已停用。

### 7.2 物料

| 字段 | 规则 |
| --- | --- |
| 编码 | 系统生成，`WL-` + 4 位流水，从 `WL-0001` 起，不可改 |
| 名称 | 必填 |
| 规格 | 选填，如阻值、封装、型号 |
| 品类 | 必填。保存品类编号，指向一条启用的品类 |
| 基本单位 | 必填，如个、只、千克、套 |
| 类型 | 生产资料或运营物资 |
| 状态 | 启用 / 停用 |

停用物料不能新建协议价，也不能加入合同。已经写进合同的名称和规格保留。

列表可按编码、名称、品类、类型、状态筛选。

## 8. 供应商

| 字段 | 规则 |
| --- | --- |
| 编码 | 系统生成，`GYS-` + 4 位流水，不可改 |
| 名称 | 必填 |
| 地址 | 必填 |
| 联系人 | 必填，一名 |
| 电话 | 必填 |
| 状态 | 启用 / 停用 |

名称允许重复，以编码区分。不做潜在、合格、暂停、淘汰等资格流转。

停用后不能新建协议价，也不能作为新合同的乙方。已有合同和已有协议价保留，可查看。

协议价本身说明这个供应商供应哪些物料，不再单独维护“可供品类”。

列表可按编码、名称、状态筛选。

## 9. 定价

一条协议价就是：这个供应商供应这种物料，当前单价是多少。

| 字段 | 规则 |
| --- | --- |
| 供应商 | 必填，且为启用 |
| 物料 | 必填，且为启用 |
| 单价 | 必填，大于 0，最多 4 位小数，人民币 |

同一供应商、同一物料只有一条当前协议价。再次保存就是改这条单价。

改价只影响之后新加入合同的明细。已经在合同里的单价不跟着变。系统不保留报价单，不把多个供应商的价格放在一起比较。

没有生效区间、折扣和价格审批。

列表可按供应商、物料、品类筛选。

## 10. 合同

### 10.1 主档

每份合同都有相同的主档：

| 字段 | 规则 |
| --- | --- |
| 合同编号 | 创建时生成，不可改。保密协议为 `NDA-年份-4位流水`，采购合同为 `CG-年份-4位流水`。同一类型、同一年从 0001 递增 |
| 合同类型 | 创建时选定，不可改 |
| 标题 | 必填 |
| 甲方 | 启用中、且可作为甲方的公司 |
| 乙方 | 启用中的供应商 |
| 经办人 | 当前采购员 |
| 签订日期 | 生效前必填 |
| 生效日期 | 生效前必填 |
| 失效日期 | 选填，若填写则晚于生效日期 |
| 状态 | 草稿、已生效 |
| 备注 | 选填，不进入 PDF |

失效日期只作记录和展示。到期后不自动改状态，也不发提醒。

列表可按编号、标题、类型、甲方、乙方、状态筛选。

类型自己的正文和明细放在扩展内容里，不放进主档。见第 11 节。

### 10.2 状态

| 状态 | 可以做什么 |
| --- | --- |
| 草稿 | 修改、删除、导出 PDF、生效 |
| 已生效 | 查看、导出 PDF。不能修改，不能删除 |

生效前要具备：甲方、乙方、标题、签订日期、生效日期、正文。采购合同还要至少有一行明细，且总价等于各行金额之和。

生效时按第 5 节把双方和明细固定下来。

草稿导出的 PDF 带“草稿”水印。已生效的 PDF 不带水印。

### 10.3 保密协议

扩展内容只有正文，纯文本，必填。保留换行。

没有富文本、表格、图片和条款模板。双方名称由 PDF 印在正文前面，不必在正文里再写一遍。

### 10.4 多物品采购合同

扩展内容包括纯文本正文，以及明细行。

添加明细时，先选这个乙方已有协议价的物料，系统带出名称、规格、单位和单价，采购员填写数量。系统计算金额。

| 内容 | 来源 |
| --- | --- |
| 名称 | 物料名称 |
| 规格 | 物料规格，可空 |
| 单位 | 物料基本单位 |
| 单价 | 当前协议价 |
| 数量 | 采购员填写 |
| 金额 | 按第 5 节计算 |

同一物料在一张合同里只出现一行。

## 11. 合同如何扩展

合同分成固定主档和按类型变化的扩展内容。

| 类型 | 扩展内容 | PDF 版式 |
| --- | --- | --- |
| 保密协议 | 正文 | 纯文本 |
| 多物品采购合同 | 正文 + 明细行 | 正文 + 明细表 |

两种类型现在就做在系统里。页面上不能再配置出一种新类型。

以后如果要增加类型，例如一份只有条款的质量协议：

- 主档、编号规则、草稿/生效、列表筛选保持不变
- 为新类型单独定义扩展内容
- 为新类型指定一种 PDF 版式。现有两种版式能表达的，就沿用；表达不了的，再增加版式

已有合同继续按它生成时的类型和内容打开、导出。

## 12. PDF

共同规则：

- A4 纵向。
- 文字型 PDF，正文和数字可以选中复制。
- 嵌入中文字体。
- 页眉为合同编号和标题。页脚为“第 n 页 / 共 m 页”。
- 导出时按合同当前内容生成 PDF，并在合同上保留最近一次导出的文件。
- 已生效合同的内容不再变化，因此重复导出的可见内容一致。

标题下、正文前印双方：

- 甲方：名称、地址
- 乙方：名称、地址、联系人、电话

正文结束后印“甲方（盖章）”“乙方（盖章）”和签订日期。不贴电子章。

### 12.1 保密协议

顺序：标题、编号、双方、正文、签字栏。

正文按录入的换行打印。不画表格，不生成条款编号。

### 12.2 多物品采购合同

顺序：标题、编号、双方、正文、“采购明细”表、合计、签字栏。

表格四列：

| 名称 | 单价 | 数量 | 总价 |
| --- | --- | --- | --- |
| 物料名称；规格有值时印在名称下方 | 协议单价 | 数量加单位，如 `10000 个` | 行金额 |

合计印在表格下面，为各行总价之和，保留两位小数。明细跨页时重复表头。

## 13. 对象关系

| 对象 | 关系 |
| --- | --- |
| 组织 | 树。公司节点可被选为甲方 |
| 人员 | 属于一个组织，登录后即采购员 |
| 品类 | 树。上级字段指向品类自身 |
| 物料 | 多对一属于品类。物料上的品类编号指向品类，必填 |
| 供应商 | 独立档案 |
| 协议价 | 一个供应商加一个物料，对应一个当前单价 |
| 合同 | 主档 + 该类型的扩展内容 |
| 采购明细 | 只属于多物品采购合同，保存加入时的名称、规格、单位和单价 |

## 14. 验收要点

**账号**

- 任意启用中的采购员都能维护全部模块。
- 停用账号不能登录。
- 开账号、改价、合同生效、导出 PDF，都不会发出邮件。

**资料与价格**

- 同一供应商的同一物料只能有一条当前协议价。修改单价后，已在合同中的单价不变。
- 停用的供应商、物料不能进入新的协议价和新合同。
- 系统中没有采购申请，没有多供应商比价页面。

**合同与 PDF**

- 没有协议价的物料不能加入采购合同，合同上也不能手填单价。
- 行金额、合同总价的计算与第 5 节一致，页面和 PDF 相同。
- 生效后修改物料名称或协议价，再次导出仍是生效时的名称和单价。
- 保密协议 PDF 没有表格，换行与正文一致。
- 采购合同 PDF 同时包含正文，以及名称、单价、数量、总价。草稿有水印，生效件没有。
